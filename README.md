# threads-bot

Бот для **Meta Threads** на официальном API. Публикация, отложенные посты, автоответы на комментарии, аналитика.

TypeScript, **ноль рантайм-зависимостей** — только встроенный `fetch`. Из зависимостей лишь `typescript` для сборки.

---

## Зачем это нужно

У официального Threads API есть заметные пробелы, которые бот закрывает:

| Чего нет в API | Что делает бот |
|---|---|
| Планирования публикаций на будущее | Своя очередь + команда `tick` для cron |
| Постов длиннее 500 символов | Команда `thread` — режет текст и публикует цепочкой |
| Автоответов на комментарии | Правила в `autoreply.json` с журналом, чтобы не отвечать дважды |
| Внятных сообщений об ошибках | Расшифровка кодов Meta с подсказкой, что делать |
| Защиты от исчерпания квоты | Проверка остатка лимита перед пакетной публикацией |

---

## Важно знать до старта: App Review не нужен

**Если бот постит в твой собственный аккаунт, проходить App Review не требуется.** Достаточно оставить приложение в режиме разработки и добавить себя как Threads Tester.

App Review понадобится только когда к боту начнут подключаться посторонние пользователи. По опубликованным отчётам разработчиков, одобрение одного scope занимает от 2–7 рабочих дней до двух недель, с высоким шансом отказа с первого раза — для личного бота всей этой процедуры можно избежать.

## Шаг 1. Настройка на стороне Meta

1. Зайди на [developers.facebook.com](https://developers.facebook.com/) и залогинься.
2. **My Apps → Create App.** В выборе сценария укажи **«Access the Threads API»** — не «Other», иначе нужные разрешения не появятся.
3. В настройках use case включи разрешения:
   - `threads_basic` — обязателен всегда
   - `threads_content_publish` — публикация
   - `threads_manage_replies`, `threads_read_replies` — работа с ответами
   - `threads_manage_insights` — аналитика
4. **App roles → Roles → Add People → Threads Tester.** Добавь свой аккаунт Threads.
5. ⚠️ **Прими приглашение**: Threads → Settings → Website permissions → Invites.
   Без этого шага приглашение висит как pending, а OAuth будет молча отбивать запросы. Это грабли №1 у новичков.
6. Укажи **Redirect Callback URI**. Для локальной работы подойдёт `https://localhost:3000/callback` — реальный сервер не нужен.
7. Скопируй **Threads App ID** и **Threads App Secret**.

⚠️ Meta генерирует **два набора** ключей. Нужны те, что в разделе Threads API.

```bash
git clone https://github.com/oma3wa/threads-bot.git
cd threads-bot
npm install

cp .env.example .env
# впиши THREADS_APP_ID, THREADS_APP_SECRET, THREADS_REDIRECT_URI
```

## Шаг 3. Авторизация

```bash
npm run bot -- login
```

Открой полученную ссылку, разреши доступ. Браузер перебросит на redirect URI и, скорее всего, покажет ошибку соединения — это нормально, сервера там нет. Скопируй из адресной строки значение параметра `?code=`.

```bash
npm run bot -- exchange "AQD...твой код..."
npm run bot -- whoami
```

Бот получит короткий токен (1 час) и **сразу обменяет на долгий** (60 дней), сохранив в `data/tokens.json` с правами `0600`.

## Команды

### Авторизация

```bash
npm run bot -- login              # ссылка для авторизации
npm run bot -- exchange <code>    # код → токен на 60 дней
npm run bot -- refresh            # продлить ещё на 60 дней
npm run bot -- whoami             # профиль и остаток срока токена
```

### Публикация

```bash
npm run bot -- post "Привет из API"
npm run bot -- post-image "С картинкой" https://example.com/pic.jpg
npm run bot -- post-video "С видео" https://example.com/clip.mp4
npm run bot -- carousel "Галерея" https://…/1.jpg https://…/2.jpg
npm run bot -- thread "Очень длинный текст…"     # разобьёт на цепочку
npm run bot -- reply <post-id> "Ответ"
```

### Отложенные посты

```bash
npm run bot -- schedule "+2h" "Пост через два часа"
npm run bot -- schedule "2026-08-01 09:30" "Пост первого августа"
npm run bot -- queue                   # что в очереди
npm run bot -- cancel <id>             # отменить запись
npm run bot -- prune                   # убрать опубликованные
npm run bot -- tick                    # опубликовать всё, чему пора
npm run bot -- tick --dry-run          # показать, но не публиковать
```

Форматы времени: `+30m`, `+2h`, `+1d`, `"2026-08-01 09:30"`, ISO-строка.

### Ответы

```bash
npm run bot -- posts 10                # последние посты
npm run bot -- replies <post-id>       # ответы на пост
npm run bot -- conversation <post-id>  # вся беседа
npm run bot -- hide <reply-id>         # скрыть ответ
npm run bot -- unhide <reply-id>
npm run bot -- autoreply --dry-run     # сначала всегда так
npm run bot -- autoreply               # затем по-настоящему
```

### Аналитика

```bash
npm run bot -- limits          # остаток суточных квот
npm run bot -- stats <post-id> # просмотры, лайки, ответы
npm run bot -- stats-account   # метрики аккаунта за 30 дней
```

## Автоматизация через cron

Очередь публикуется только тогда, когда вызвана команда `tick`. Поставь её в cron:

```cron
# Публикация отложенных постов — каждые 10 минут
*/10 * * * * cd /path/to/threads-bot && npm run bot -- tick >> data/tick.log 2>&1

# Продление токена — раз в неделю (токен живёт 60 дней)
0 4 * * 1 cd /path/to/threads-bot && npm run bot -- refresh >> data/refresh.log 2>&1

# Автоответы — раз в час
0 * * * * cd /path/to/threads-bot && npm run bot -- autoreply >> data/autoreply.log 2>&1
```

**Продление токена — не пропускай.** Долгий токен живёт 60 дней; продлевать можно после первых 24 часов и до истечения. Пропустил окно — придётся заново проходить OAuth. Бот предупреждает, когда осталось меньше 10 дней.

Отдельный нюанс: если профиль приватный, выданные разрешения истекают через **90 дней** независимо от токена — это второй, независимый таймер.

## Автоответы: настройка

```bash
cp autoreply.example.json autoreply.json
```

```json
{
  "maxPerRun": 5,
  "rules": [
    {
      "pattern": "спасибо|благодар",
      "responses": ["Рад, что пригодилось!", "Спасибо, что читаешь"]
    }
  ]
}
```

- `pattern` — регулярное выражение, регистр не важен
- `responses` — варианты ответа, выбирается случайный (шаблонные ответы выглядят как спам)
- `maxPerRun` — предохранитель: не больше N автоответов за прогон

Встроенные защиты: бот **никогда не отвечает сам себе** и не отвечает дважды на один комментарий — иначе устроит бесконечную переписку с собой. Обработанные комментарии пишутся в `data/replied.json`.

**Всегда проверяй сначала с `--dry-run`.**

## Лимиты официального API

| Операция | Лимит | Окно |
|---|---|---|
| Публикация постов | 250 | 24 часа |
| Ответы | 1 000 | 24 часа |
| Удаления | 100 | 24 часа |
| Поиск по ключевым словам | 500 | **7 дней** |

Карусель из 20 изображений считается как **один** пост. Команда `limits` показывает актуальный остаток.

## Чего API не умеет вообще

- Планирования на будущее (закрыто очередью бота)
- Черновиков
- Редактирования поста после публикации
- Массового чтения чужого контента — доступен только свой аккаунт
- Stories

## Как устроена публикация

Одним запросом опубликовать нельзя — всегда два шага:

1. `POST /{user-id}/threads` → создаётся контейнер
2. `POST /{user-id}/threads_publish` с `creation_id` → публикация

Между шагами контейнер должен перейти в статус `FINISHED`. Документация советует «подождать 30 секунд», но это плохой совет: для текста готово почти сразу, а видео может обрабатываться дольше. Бот **опрашивает статус** с растущим интервалом (2→8 с), а не спит фиксированное время.

## Безопасность

- `data/tokens.json` создаётся с правами `0600` — читать может только владелец
- Токен **никогда не печатается целиком**: в логах только последние 4–6 символов
- Весь вывод проходит через `redact()`, который затирает `access_token` и `client_secret` — иначе токен утёк бы в логи cron, ведь Graph API принимает его как query-параметр
- `.env`, `data/tokens.json` и логи закрыты в `.gitignore`

## Если что-то не работает

| Симптом | Причина и решение |
|---|---|
| `code 190` | Токен истёк или недействителен → `refresh`, иначе `login` заново |
| `code 200` / permission | Scope не выдан → проверь разрешения приложения и переавторизуйся |
| OAuth молча отбивает запрос | Не принято приглашение Threads Tester в настройках Threads |
| Контейнер в статусе `ERROR` | URL медиа недоступен публично или формат не поддерживается |
| `code 4` / `code 32` | Превышена частота → увеличь `THREADS_THROTTLE_MS` |
| Ответ не JSON | Неверный хост → попробуй `THREADS_GRAPH_HOST=https://graph.threads.com` |

Подробный вывод запросов: добавь флаг `--debug`.
